# Правила оформления README

Эти правила относятся к README этой ветки. Сохраняй существующие файлы заданий, решений и ссылки на них.

## GitHub-сноски

Используй стандартные GitHub Alerts в формате:

```markdown
> [!NOTE]
> Короткое пояснение по теме ветки.
```

Выбирай тип по смыслу:

- `NOTE` — контекст, уточнение или полезное пояснение.
- `TIP` — практический совет или способ упростить работу.
- `IMPORTANT` — ключевое требование или принципиальный результат.
- `WARNING` — возможная проблема, на которую нужно обратить внимание.
- `CAUTION` — рискованное действие с вероятными последствиями.

## Тон и количество

- Пиши официально, кратко и по теме конкретной ветки.
- Добавляй сноску только тогда, когда она выделяет полезную информацию.
- Обычно достаточно одной сноски на README; не более двух, если обе нужны.
- Не дублируй в сноске заголовок, название файла или текст рядом.
- Не превращай все задания и описания в сноски. Основной материал оставляй обычным Markdown-текстом.
- Не используй эмодзи, декоративные символы и произвольные HTML-стили для имитации цвета.
- Не добавляй предупреждения без фактической причины и не придумывай требования.

## Структура и читаемость

- Размещай тематическую сноску после заголовка и краткого описания раздела.
- В каждой строке сноски ставь `>`; отделяй сноску пустыми строками от соседнего текста.
- Для задания и решения сохраняй отдельные подписи, ссылки с точными именами файлов и краткие описания.
- Разделяй несколько заданий тонким `<hr>` с пустыми строками вокруг него.
- Внизу README оставляй отдельный раздел `Весь курс` со ссылкой на `main`.
- Не изменяй README ветки `main`, если это отдельно не поручено.

## Пример

```markdown
> [!TIP]
> При настройке сети проверьте адрес интерфейса и доступность узла.
```
